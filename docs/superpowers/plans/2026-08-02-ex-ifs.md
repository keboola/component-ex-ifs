# keboola.ex-ifs Extractor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Each task names the **owning component skill** the executing subagent must load, so it stays Keboola-aware: implementation → `component-develop` (which delegates schema/UI to `component-build-ui`); tests → `component-test` / `generate-vcr-tests`; portal → `component-dev-portal`; deploy → `component-test` (tier 4) + `kbagent`; final audit → `component-checklist-review` + `babysit-pr`.
> Source of truth for scope/design: `docs/superpowers/specs/2026-08-02-ex-ifs-design.md`. Build tracker: `docs/superpowers/keboola.ex-ifs-lifecycle.md` (local, gitignored) — tick Phases 4–8 there as each milestone verifies.

**Goal:** Build a single, generic, config-driven Keboola extractor for IFS Cloud OData v4 projection services, with live schema discovery, native types, and incremental loading. Domain-neutral — `VoucherRowsAnalysis` is used only as one example/test fixture (chosen because its OpenAPI is on disk), not a privileged domain.

**Architecture:** Config rows (one row → one output table) on a shared root connection. A separated client layer — Keycloak `client_credentials` auth (token cache + mid-run refresh; a single concrete auth client, no multi-grant seam), an OData client (nextLink paging + `$skip` fallback, meta-field stripping), and an EDMX `$metadata` parser — feeds a thin `run()` orchestrator that streams rows to a `schema`-manifest CSV and advances a per-row watermark. Sync actions drive UI dropdowns from the tenant catalog and per-service metadata.

**Tech Stack:** Python 3.12+, `keboola.component` (Common Interface), `pydantic` v2 (config models), `requests` (HTTP), stdlib `xml.etree.ElementTree` (EDMX), `pytest` + `keboola.datadirtest` + VCR (tests). Mirrors the private sibling `keboola.ex-sap-odata`.

## Global Constraints

- **No customer identifiers in any committed file.** Never write the real tenant/realm/host into code, schema, tests, cassettes, or commit messages. Use placeholders `{tenant}` / `{host}` (`{tenant_id}.ifs.cloud`) / `{realm}` / `{client_id}`. Test/fixture example values use generic public codes (e.g. company `100`), never the customer's granted company.
- **Auth grant: `client_credentials` only.** `password` (ROPC) is not built and **no `auth_type` switch or seam** is introduced for it (spec §4.2, maintainer decision). Auth is a single concrete client.
- **Server-side access is NOT component config.** IFS Permission Sets/roles (`IFSREADONLYSUPPORT`) and Allowed Companies are provisioned on the service account **inside IFS** — external prerequisites, not config fields or auth logic (spec §3.1). Least privilege: setup docs request only the proven-sufficient grant, never broader. A `403`/empty result is surfaced as a diagnostic, not managed by the component.
- **Token TTL is short (~180 s).** The client must cache to `expires_in` and refresh mid-run (safety margin + on `401`). Never hard-code the TTL.
- **Native types:** emit the authoritative `schema` manifest (`data_type.base.type`); run tests with `KBC_DATA_TYPE_SUPPORT=authoritative`; set `dataTypeSupport=authoritative` and `default_bucket=true` in the Developer Portal (Phase 6).
- **Types come from EDMX `$metadata`, not the lossy `$openapi`.** Incremental filter uses `gt`, not `ge`.
- **Secrets `#`-prefixed** (`#client_secret`); Pydantic alias must match the schema key exactly. Scratch files → `/tmp`, never `data/out/tables/`. `UserException` → exit 1; unexpected → exit 2.
- **Modern typing:** built-in generics (`list`/`dict`, not `typing.List`); `collections.abc` iterators; type hints on public methods; ruff `UP` ruleset. `run()` under ~30 lines.

```python
import time
import requests
from keboola.component.exceptions import UserException

_REFRESH_MARGIN_S = 30

class IfsAuthClient:
    def __init__(self, host, realm, client_id, client_secret,
                 scope="openid microprofile-jwt", session=None, timeout=60):
        self._host, self._realm = host, realm
        self._cid, self._secret, self._scope = client_id, client_secret, scope
        self._session = session or requests.Session()
        self._timeout = timeout
        self._token: str | None = None
        self._expires_at: float = 0.0

    @property
    def token_url(self) -> str:
        return f"https://{self._host}/auth/realms/{self._realm}/protocol/openid-connect/token"

    def invalidate(self) -> None:
        self._token, self._expires_at = None, 0.0

    def get_token(self) -> str:
        if self._token and time.monotonic() < self._expires_at - _REFRESH_MARGIN_S:
            return self._token
        resp = self._session.post(self.token_url, data={
            "grant_type": "client_credentials", "client_id": self._cid,
            "client_secret": self._secret, "scope": self._scope,
        }, headers={"Content-Type": "application/x-www-form-urlencoded"}, timeout=self._timeout)
        if resp.status_code != 200:
            raise UserException(f"IFS token request failed ({resp.status_code}). "
                                "Check tenant, realm, client id and secret.")
        body = resp.json()
        self._token = body["access_token"]
        self._expires_at = time.monotonic() + int(body.get("expires_in", 180))
        return self._token
```
